## Enforcer Shift（默认技能 Shield Tackle，EnforcerShieldTackleCharged）

- 松开 T：本地进入 `ProxyShieldDash.OnEnter`，调 `ActivateVehicle`；动画/音效等 `vehicleEnteredState`，即 T+RTT 才开始。
- T+U：服务器收到 msg48，`new VehicleShieldDashHeavy`、`AssignPassenger`。位移和 `OverlapAttack` 只在服务器跑（`if (!isAuthority) return`），客户端 `inOverlapAttackAuthority` 为 null。
- T..T+RTT：客户端 CharacterMotor 未禁用，可自由移动；vehicle/seat 到达后 `VehicleSeat.FixedUpdate` 用 `Motor.SetPosition` 硬贴 → 回拉。
- vehicle 位置约 20Hz 同步 + 68ms 插值，客户端看到的冲刺比服务器晚 U+68ms。
- 退场：`VehicleShieldDashExit` → `OnPassengerExitAuthority: Motor.SetPosition(...)`，约向前跳 2-3m。
- 转向每帧 `CmdUpdateTurn`，dedicated 服务器上方向冻结。

策略（客户端 only 可行）：1) 本地即时动画/音效/特效；2) 退场位置平滑；3) ghost dash（高风险）。双端 vehicle 客户端权威不可行（伤害消失）。

## Loader 副技能（钩爪）

- `LoaderHook` / `LoaderYankHook` prefab：`allowPrediction=0`，所以按下后客户端不生成任何钩子，只发 msg49；服务器生成并 `SpawnWithClientAuthority`，位置经 SyncVar（1/30s）+33ms 插值给客户端。
- 命中由服务器用**实时**敌人位置判定；客户端看到的敌人是插值旧位置（Beetle 0.2s，Loader 本体 0.15s）→ 瞄准提前量不足是"钩不中"的主因。
- 命中后 stuck 状态下发，owner 才进入 Grip（默认技能 `yankMassLimit=0` 永远 Grip，只拉自己）→ 自拉延迟 ≈ RTT + 飞行时间。
- 飞行 0.222s 超时从客户端收到钩子起算，最大射程命中可能撞超时。

策略（客户端 only 可行）：1) 运行时把 prefab `allowPrediction=1` 恢复 vanilla 预测；2) 在 `TrajectoryAimAssist` 之后按 目标速度×(U+0.2s+飞行) 修正瞄准。主机 only 的滞后补偿和 alt 即时 Yank 不在范围内。

## 追加（2026-10-24，真实房间日志 + 反编译复核）

日志：`C:\Users\Wray\AppData\Local\Temp\lg\out2.txt`（旧版 dll，23 次幽灵冲刺；14 次 `handoff gap too large`、7 次 `timeout`、2 次 `dash state exited`、0 次成功交接、7 次 `stuck fallback -> Main`）。

1. **gap≈幽灵位移的真实原因不是阈值，而是座位到达帧的位置是旧的**。`VehicleShieldDashMain.OnEnter`（`EntityStates.Enforcer/VehicleShieldDashMain.cs:20-30`）在非权威端 `SetReceiveUpdatesRemote(false)`，载具在客户端一直停在 `ActivateVehicle` 放下的上报起点；`VehicleShieldDashHeavy.OnEnter`（:142-143）收到 msg48 才 `ClearSnapshots` 并开始收服务器快照，第一帧快照后才把车拉到服务器当前位置。座位 SyncVar 与载具状态 msg48 同帧到达（日志 arrival #2/#3 相差 1ms），所以交接判定看到的 seat 仍在上报起点，gap≈幽灵已走距离（12.3m）→ 旧 10m 阈值必然放弃。把阈值加大只会变成“向后 blend 12m”，更糟。
2. **幽灵自身多走了 25%**：旧实现 `GhostStepSeconds(delta, traveled, StartLeadCapSeconds=0.25)` 在冲刺 `Duration=0.2s` 后仍以 curve=1 的速度走到 0.25s，所以 10m 的冲刺被模拟成 12.5m。即使阈值问题解决，幽灵也会比服务器终点远 2.5m。
3. **StartLead 被抑制使服务器终点更靠后**：旧版幽灵拥有冲刺时不写 lead，服务器载具终点=S0+10m，而幽灵最多到 S0+12.5m；仅靠“等载具追上幽灵”会死等，旧代码因此只能超时放弃。正确做法是两者共用同一个 lead：上报 S0+v·U（0.25s/墙封顶），幽灵按“lead 段 + 完整冲刺曲线”模拟，终点=S0+lead+10m=服务器终点。
4. **兜底超时确实过紧，且超时值在中途被重算**：日志 13:45:08.725 fallback（进入时 timeout 1.50s，fallback 时 timeout 0.54s，因为 RTT 从 1.011s 掉到 0.359s 后每帧重算），13:45:08.734 载具到达，仅差 9ms；13:42 段 arrival 相对松键 0.26–0.62s（1.0–2.4×当时 RTT 估计），高 RTT 日志 arrival 0.95s。`max(1.5×RTT,0.3)` 在低 RTT 下必然早退。改为进入时缓存 `max(3×RTT,1.0s)`、上限 `FeedbackFallbackMaxSeconds`，且 RTT 取 `max(游戏上报, 实测中位数)`。
5. **交接窗口的真实上限是座位寿命，不是 hold 超时**：服务器在载具冲刺结束时 `VehicleShieldDashExit.OnEnterServer` 立即 `EjectPassenger`（`VehicleShieldDashExit.cs:146-160`），客户端约在座位到达后 0.2–0.35s 收到弹出（日志 36.050→36.384）。所以交接必须在这之前完成；完不成时由 `VehicleShieldDashExit.OnPassengerExitAuthority`（:124-144）硬贴，已由 EnforcerExitSmoothing 兜底。
6. 动画复位：旧日志无“层卡死”直接证据（用户主观反馈）；上一轮的 Proxy→非 Proxy 幂等 `ShieldTackleExit` 复位覆盖 fallback/打断/死亡/关闭/熔断；座位到达后 Proxy 状态退出不再终止幽灵（位置由座位管），复位仍由该钩子负责。
